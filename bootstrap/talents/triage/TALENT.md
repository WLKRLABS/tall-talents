# Goal

Turn incoming issues into a clear state: waiting for triage, waiting for reporter information, ready for an agent, ready for a human, or intentionally not being actioned.

# Procedure

## 1. Load Tracker And Label Configuration

Confirm where issues live and how canonical roles map to tracker labels. If the repo does not define this, run or create the setup covered by `setup-matt-pocock-skills` before writing labels or comments.

Canonical category roles:

- `bug` - something is broken
- `enhancement` - new feature or improvement

Canonical state roles:

- `needs-triage` - maintainer needs to evaluate
- `needs-info` - waiting on reporter
- `ready-for-agent` - fully specified and agent-ready
- `ready-for-human` - needs human implementation
- `wontfix` - will not be actioned

Each triaged issue should carry exactly one category role and one state role. If state roles conflict, stop and ask the maintainer.

## 2. Show What Needs Attention

When asked for a queue, present three buckets oldest first:

- unlabeled issues
- `needs-triage`
- `needs-info` issues with reporter activity since the last triage notes

Show counts and one-line summaries, then let the maintainer pick the next issue.

## 3. Triage A Specific Issue

Gather the complete issue context:

- body
- comments
- labels
- reporter
- dates
- prior triage notes
- related out-of-scope records
- relevant code, docs, CONTEXT.md, and ADRs

Then recommend:

- category role
- state role
- reasoning
- brief codebase summary relevant to the issue

Wait for maintainer direction unless the user explicitly asked for a direct state move.

## 4. Reproduce Bugs Before Grilling

For bug reports, attempt reproduction before asking design or clarification questions:

- follow reporter steps
- trace relevant code
- run tests or commands
- report successful repro, failed repro, or insufficient detail

A confirmed repro should be included in the agent or human brief.

## 5. Grill Only When Specification Is Missing

If the issue needs more shape, use `grill-with-docs` to clarify the domain, behavior, and acceptance criteria. Capture resolved facts so the next pass does not re-ask answered questions.

## 6. Apply The Outcome

Use the matching action:

- `ready-for-agent` - post an agent brief
- `ready-for-human` - post the same kind of brief and state why it needs human judgment
- `needs-info` - post specific questions and what is already established
- `wontfix` bug - explain politely and close
- `wontfix` enhancement - record the rejection in `.out-of-scope/`, link it, and close
- `needs-triage` - apply the role, with an optional progress note

All generated tracker comments must begin:

```markdown
> *This was generated by AI during triage.*
```

## 7. Resume Without Repeating Work

When an issue already has triage notes:

- read the notes first
- check whether the reporter answered open questions
- update the picture before continuing
- do not re-ask resolved questions

## Needs-Info Template

```markdown
> *This was generated by AI during triage.*

## Triage Notes

**What we've established so far:**

- [fact]

**What we still need from you (@reporter):**

- [specific actionable question]
```

# Success Criteria

- Every issue gets one category role and one state role.
- Maintainer sees a clear recommendation before irreversible issue actions.
- Bug issues include a real reproduction attempt when possible.
- Agent-ready issues contain enough context for AFK work.
- Needs-info questions are specific and preserve what was already learned.

# Common Failure Modes

- Applying duplicate or conflicting state labels.
- Asking for "more info" without naming the missing detail.
- Writing an agent brief without checking prior triage notes.
- Skipping bug reproduction and pushing vague reports to agents.
- Posting generated issue comments without the required AI triage disclaimer.

# Example Prompt

"Use `triage` on issue #42. Read the full issue and prior comments, check the label state, try to reproduce if it is a bug, recommend the category and state, and prepare the correct triage comment or agent brief."
